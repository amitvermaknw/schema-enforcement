\section{Threats to Validity}
\label{sec:threats}

We organise threats by the construct, internal, external and conclusion
validity classification of \citet{wohlin2012experimentation}.

\paragraph{Construct validity.}
The taxonomy is an operational diagnostic for the prompt-and-validate
paradigm, not a complete account of structured-output failure. Primary
categories are single-valued, labels follow how a constraint is encoded
rather than what it intends (\cref{sec:setup:taxonomy}), and we quantify
co-occurrence only beneath fences. Human checks of the classifier come from a single labeller who also
wrote it. The development check displayed the classifier's label and is
not independent; the pre-registered held-out check was blind and gives
\pn{heldout.rate} agreement, but covers only the three categories with
attempts left after development, and no second annotator labelled either
sample, so we report no inter-annotator agreement. Three properties limit what this can affect.
Stage-1 categories are syntactic predicates on the raw completion, and
corpus-wide screens that do not depend on any human label find no
missed case among the failures they match (\cref{app:classifier}). Stage-2 categories are a fixed map
from the Pydantic error types stored with each attempt, and rerunning the
released classifier over the database reproduces every stored label.
Disagreements in both checks were resolved against the stored error
record or the raw completion, not the labeller's judgement. The residual
risk lies in the category definitions and the precedence rule rather than
in label noise; we release the annotations and stored completions so that
an independent labeller can test both. We evaluate conformance only, not whether extracted content
is correct. Among attempts whose model-level validators ran, no
cross-field violation occurred (\cref{app:crossfield}), but attempts
rejected earlier, including during JSON parsing, never reached those
checks, so the zero describes a filtered subset of the node-level
validators we implemented. Cross-node referential integrity, whether a
later node's identifiers appear in an earlier node's entities, is not
implemented in our schemas; it is expressible in Pydantic by passing the
earlier output as validation context
(\code{model\_validate\_json(data, context=\ldots)}) and is the natural
next measurement.

\paragraph{Internal validity.}
Repair attempts, which are conditioned on a prior failure, make up a
model-dependent share of each attempt rate; first-attempt rates and run
completion are reported separately for that reason
(\cref{app:breakdowns}). Every retry carries the validation error and no
condition retries without it, so the design does not separate the effect
of the feedback from that of a further attempt. Five models reject an
explicit temperature, and the Anthropic and OpenAI branches use
different token ceilings. Some questions were run more than once; keeping
only the earliest run per question changes any cell's failure rate by at
most \pn{robust.within_cell.max_abs_delta_pp} percentage points
(\cref{app:manifest}). The prompt ablation is exploratory: the variant
cells (\pn{ablation.aggressive.attempts} and \pn{ablation.few_shot.attempts}
attempts against \pn{ablation.baseline.attempts}; \cref{tab:ablation}) were
run after the final baseline batch
rather than interleaved with it and are not paired by question, so
differences between conditions may reflect question composition or
collection time as well as prompt wording. We use it only to show how
concealment changes the reading of failure labels, and draw no conclusion
about prompt effectiveness; a matched, interleaved rerun would be needed
for that.

\paragraph{Which comparisons are matched.}
Across all nine configurations, the HotpotQA cells at the medium tier
share the schema, the baseline system prompt, the retry budget of three
further attempts, and the same
\pn{matched.hotpotqa_medium.shared_questions}-question prefix (\cref{tab:manifest});
these cells are the matched basis for cross-model comparison. The
pooled per-model figures in \cref{tab:models} and \cref{fig:profiles}
also include FinanceBench for six models; per-cell results are in
\cref{tab:domains}. They are not matched in sampling or collection: four
configurations run at \code{temperature=0} and five at provider
defaults, the Anthropic branch sets an output-token ceiling that the
OpenAI branch does not, collection dates range over three weeks
(\cref{tab:provenance}), and the number of runs per question varies by
cell, most for Haiku~4.5 (\cref{tab:manifest}). FinanceBench was
run for six of the nine models, so domain comparisons are within-model
only, and each schema variant was run on one or two models, so
constraint-surface comparisons are within those models. We therefore
describe differences between configurations and do not attribute them to
model capability alone.

\paragraph{External validity.}
The schemas are ours, and one ablation showed that a cap we set was
binding below the output lengths of one model; a different author would
produce a different distribution over categories, and the domain
comparison shows that a different task would too. We cover two vendors by
design, trading breadth for several generations and capability tiers per
vendor, which the within-family comparisons require; a third vendor or an
open-weights model may exhibit modes our taxonomy lacks. We do not
compare against constrained decoding or vendor structured-output modes
(\cref{sec:related}), so we make no claim about how often those
configurations would prevent the failures we report. Questions are fixed
dataset prefixes, the design is not fully crossed, and most failures in
this corpus come from a single model. Most endpoints returned an alias
rather than a pinned version, so later calls to the same identifier may
not reproduce these distributions.

\paragraph{Conclusion validity.}
Attempts are not independent, so all intervals are question-clustered
bootstrap intervals (\cref{sec:setup:basis}) that describe variability
over the observed question set, not over the benchmarks. We do not
interpret cells with a handful of failures, and we treat maximum-gap
divergence statistics as secondary because they are selected to be
extreme (\cref{app:divergence}).
