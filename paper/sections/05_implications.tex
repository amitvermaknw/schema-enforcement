\section{Implications for Practice}
\label{sec:implications}
\label{sec:discussion} % kept so existing \cref{sec:discussion} still resolves

Each practice below follows from a specific finding and targets one
component of a prompt-and-validate pipeline: the validator, the schema,
the retry loop, or the way the pipeline is evaluated
(\cref{tab:practices}). The first, second and fourth are supported at the
scale of this corpus; the third is a design implication of our findings
that we did not test.

\paragraph{Validator: strip fences, then revalidate and record what remains.}
Fence removal is a partial repair: it recovers the pure-formatting share
of wrapped failures, which ranged from most of Sonnet~5's to under half
of Haiku~4.5's (\cref{sec:results:concealment}). A pipeline that counts
fence removal as a fix would report the compound remainder as solved.

\paragraph{Schema: separate conflated causes and set caps from data.}
A \code{\{2,30\}} quantifier turns an over-long identifier into a pattern
violation, and the natural remedy for a pattern violation, loosening the
character class, leaves it untouched (\cref{sec:results:surface}). A
separate \code{max\_length} separates the causes at validation time.
Caps should likewise be set from a field's observed length distribution.
Sonnet~4.6's dominant mode came from caps sitting modestly below its
output lengths, and Haiku~4.5's incomplete runs all ended on length. Such
a cap may still be a real downstream requirement; the measurement
identifies the mismatch the application must resolve, not that the cap
is wrong.

\paragraph{Retry loop: give the model the violation it must fix.}
The error returned for a fenced output is a JSON parse error, so the
repair loop learns of a concealed length violation only on a later
attempt: of the run-nodes that exhausted their retries, most received the
length error only once (\cref{sec:results:concealment}). Validating the
fence-stripped payload before composing the retry message would name the
underlying violation on the first retry. We did not run this variant, so
we do not claim it would reduce exhaustion; it is the natural design
change our data point to.

\paragraph{Evaluation: report composition, not only a rate.}
Over this corpus the attempt-weighted failure rate is largely a statement
about one configuration (\cref{sec:results:rates}), and reading primary
labels alone makes a prompt ablation appear to move failures from
wrapping to length (\cref{sec:results:concealment}). Evaluating a
pipeline change should therefore report the failure composition per
configuration, including violations concealed beneath fences, before
concluding that the change removed a failure.

\paragraph{Will these modes persist?}
A reasonable objection is that providers are engineering these modes
away. Our cross-generation data are descriptive and do not isolate model
generation from other configuration differences, including collection
date, sampling parameters and endpoint. With that caveat, they point in
both directions: \cat{schema\_mirroring} dominates gpt-4o and was not
observed in the GPT-5.6 configurations we tested, while
\cat{markdown\_wrap} was not observed in Sonnet~4.6 and dominates
Sonnet~5 and Haiku~4.5. What differs across these models is which
category dominates. A vocabulary for the categories remains useful as the
distribution moves, which is a weaker claim than predicting that any
particular mode persists.
