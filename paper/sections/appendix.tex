seed. Collection ran from \pn{collection.date_min} to
\pn{collection.date_max}; per-cell date ranges and distinct-question
counts are in \cref{tab:manifest}. The Haiku~4.5 FinanceBench cell covers
\pn{c.claude-haiku-4-5@medium@financebench.questions} distinct questions,
fewer than the other FinanceBench cells. Exact question identities, as
dataset record hashes, are in the released \code{question\_manifest.csv}.

\paragraph{Resolved versions and request parameters.}
Only the Haiku request names a dated snapshot, which was returned
unchanged. \code{gpt-4o} resolves to \code{gpt-4o-2024-08-06} and
\code{gpt-4o-mini} to \code{gpt-4o-mini-2024-07-18}; the Anthropic models
and the GPT-5.6 family return the requested alias, which identifies the
endpoint but not an immutable model version, so later calls to the same
identifier may not reproduce these distributions. Version capture was
added after the first sweeps: \pn{versions.gpt-4o.precapture} of
\pn{versions.gpt-4o.attempts} \code{gpt-4o} attempts and
\pn{versions.gpt-4o-mini.precapture} of \pn{versions.gpt-4o-mini.attempts}

\Cref{tab:provenance} gives the requested and returned identifiers, the
API route, the collection window and the sampling parameters sent by the
client for each model.

\paragraph{Validator version.}
The Pydantic version used during collection was not recorded; the
harness then required version 2.7 or later within major version 2.
Analysis used pydantic 2.13.4 with pydantic-core 2.46.4, which the

The Haiku~4.5 HotpotQA baseline cell contains \pn{robust.cell.runs} runs

report a pooled rate under deduplication: it removes mostly Haiku~4.5
attempts, so the pooled change reflects reweighting between models rather
than sensitivity to repetition.

\section{Classifier Validation}
\label{app:classifier}

\paragraph{Provenance.}
Hand labelling was performed against an earlier classifier in which
Pydantic error-type mapping preceded the behavioural predicates.
Schema-mirrored outputs were consequently labelled \cat{missing\_field}
and prose-preamble outputs \cat{parse\_error}. We corrected the order and
reclassified the full corpus from stored completions and error details,
without new model calls. Running the released \code{reclassify\_all.py},
which applies both stages of \code{errors.py}, in dry-run mode over the
released database reproduces the stored primary label of all
\pn{full.failures} failed attempts (zero changes).

\paragraph{Agreement.}
The sample was drawn from all \pn{full.failures} failures in the corpus,
including pilot cells and prompt variants. \Cref{tab:validation} reports
precision and recall of the corrected classifier against the \emph{blind}
human labels. The four disagreements were adjudicated as labelling
errors: three outputs labelled \cat{enum\_violation} carried a
\code{string\_pattern\_mismatch} on an identifier, and one labelled \cat{markdown\_wrap} contained no fence. The first three
are checkable against the stored error record and the fourth against the raw
completion, without reference to the labeller. We headline blind agreement
because adjudication uses evidence the labeller did not consult. The sample
contains every \cat{enum\_violation}, \cat{prose\_preamble} and
\cat{schema\_mirroring} failure in the corpus, so a held-out check with a
frozen classifier can test only the remaining categories.

\paragraph{Corpus screens.}
Because the sample is stratified by predicted label, it cannot establish
corpus recall. For the Stage-1 categories we screened every failure in the full corpus
with relaxed screens for wrapping and preambles, and a keyword-restricted
screen for mirroring. A fence at
any position matches \pn{screen.fence_any.matches} failures, of which
\pn{screen.fence_any.markdown_wrap} are classified \cat{markdown\_wrap}
and \pn{screen.fence_any.prose_preamble} \cat{prose\_preamble} (prose
before a later fence). A \code{"properties"} key matches
\pn{screen.properties.matches} failures, of which
\pn{screen.properties.schema_mirroring} are classified
\cat{schema\_mirroring}; this screen tests one meta-keyword where the
detector requires two, so it checks for missed mirroring cases only among
failures containing that key. An opening character other than a brace, bracket or fence
matches \pn{screen.nonjson_opener.matches} non-empty failures, of which
\pn{screen.nonjson_opener.prose_preamble} are \cat{prose\_preamble}.

corpus. First-attempt validity is non-zero for every other model under the

\section{Model-Level Constraints}
\label{app:crossfield}

Model validators run only after every field-level constraint passes.
On the reporting basis, \pn{crossfield.reached} attempts reached them:
\pn{crossfield.validated} that validated and \pn{modellevel.violations}
that passed field validation and failed the per-item
supporting-identifier check in the answer validator. That check follows
the confidence-bucket check in the same method, so those attempts also
passed it. No attempt matched any of the four cross-field messages
(\pn{crossfield.violations} violations). The remaining
\pn{crossfield.not_reached} failures did not reach the validators; many
failed during JSON parsing. Each node tests only its own checks: two
cross-field checks in identify, one in gather, and one cross-field plus
one per-item pattern check in answer. \pn{hidden.exhausted_attempts} of the
\pn{hidden.n} are the final attempts of one gpt-4o-mini answer node, which
exhausted its retries although each returned error named the required
pattern; it is that model's only incomplete run. Excluding all
\pn{hidden.n} changes no cell's or group's dominant category; gpt-4o-mini's
\cat{regex\_pattern} share moves from
\pn{g.gpt-4o-mini@medium.dominant_share} to
\pn{hidden.gpt4omini.share_without}.

\paragraph{Prompt visibility.}

\section{Divergence Metric}
\label{app:divergence}

For each pair of model--tier groups and each category we take the
absolute difference in the share of the group's failures held by that
category. Groups pool task domains and use the reporting basis; of
\pn{divergence.groups_total} groups with any failure,
\pn{divergence.groups_qualifying} have at least 20 failures, giving
\pn{divergence.pairs} pairs. The two largest values arise on different
categories from opposite vendors, \pn{divergence.top.0.pp} and
\pn{divergence.runner_up_category_pp} points, and differ by
\pn{divergence.gap_pp} points, so we attach no significance to their
order. The maximum of \pn{divergence.top.0.pp} points is itself attained
by \pn{divergence.top.n_tied} pairs, each setting Haiku~4.5 against a
group with no \cat{markdown\_wrap} failures. Without the threshold the
maximum is \pn{divergence.unrestricted.max.pp} points in
\cat{regex\_pattern}, attained by \pn{divergence.unrestricted.max.n_tied}
pairs, Haiku~4.5 at medium against each of gpt-5.6-sol and gpt-5.6-terra
at medium\_v3, whose failures are all \cat{regex\_pattern}; those groups
have very few failures. Maximum-gap statistics are selected to be extreme
and do not summarise the distributions; we report them as secondary.
